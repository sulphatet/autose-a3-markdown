# ADR-001: Five agents with closed contexts, and a script for release

**Status:** Accepted
**Date:** 2026-11-21
**Decision area:** D1, splitting the work

## Context

The workflow has six fixed stages. Each stage needs different knowledge and different rights:

- Requirements works on untrusted issue text and must not invent anything (the A1 skill rules).
- Design needs a map of the codebase (`ARCHITECTURE.md` from A2).
- Implementation needs write access to source files.
- Testing must judge the implementation, so it should not share the implementer's assumptions.
- Release needs push rights and nothing else.
- Review must be independent of everything before it.

One long-running agent that holds all of this in one context would carry its own earlier reasoning into every later stage. A tester that remembers why the implementer wrote the code a certain way tends to write tests that confirm the code, not the spec. The same goes for a reviewer.

## Decision

Five LLM agents and one deterministic script:

| Agent | Stages | Sees | Writes |
| --- | --- | --- | --- |
| Spec agent | 1 Requirements | issue, A1 skill | `spec.md` (+ A1 register, validation, evidence files) |
| Designer | 2 Design | issue, spec, `ARCHITECTURE.md`, repository (read-only) | `design.md` |
| Implementer | 3 Implementation | issue, spec, design, repository, failing-test or review feedback | source changes → `diff.patch` |
| Tester | 4 Testing (writes tests) | spec, design, repository with the change applied | test files |
| Reviewer | 6 Review | issue, PR diff, repository at PR head | `review.md` |
| Release script (no LLM) | 5 Release | branch, artifacts | push, PR, `pr.md` |

The contexts are closed. No agent receives another agent's conversation or reasoning. Agents pass work to each other only through artifact files (ADR-003).

When tests fail, the implementer receives only the failure output (test name, assertion, traceback). It does not get the tester's reasoning. The tester never sees the implementer's conversation, only the code as it now is in the repository.

Running the test suite in stage 4 is done by code, not by the tester agent (ADR-007). The tester only writes tests.

## Alternatives considered

- **One agent for all stages.** Simplest, and it has the most context. Rejected because the implementer's reasoning leaks into the tests and the review, and because one agent would need the union of all permissions (ADR-005).
- **One agent per stage (six agents).** Release is a fixed sequence (`git push`, `gh pr create`, wait for CI). An LLM adds cost and failure modes there and no judgement. A script is deterministic and can hold the push credential without exposing it to a model.
- **Merge spec and design into one agent.** Fewer calls. Rejected because the A1 skill forbids design in the spec ("If you notice yourself choosing frameworks … stop"), and keeping them apart lets the stage 1 check reject a vague issue before any design tokens are spent.
- **Implementer writes its own tests.** Common in practice and cheaper. Rejected as the default, and kept as a variant for the D1 experiment (`experiment/variants.md`).

## Consequences

- The tests are written against the spec, so they can catch an implementation that is wrong but consistent with itself.
- The tester can misread the API, because it does not know the implementer's intent. The design names the functions to change (ADR-007, stage 2 check), which gives the tester a shared contract.
- Five agents means five prompts to maintain and more model calls, which matters on the free tier (ADR-006, ADR-009).
- If a test is wrong rather than the code, the implementer cannot tell from the failure output alone. The fail-to-pass check (ADR-007) reduces this, and the redesign fallback (ADR-002) limits how long it can loop.

## How we will know if this is wrong

If the separate tester's tests fail on correct implementations more often than they catch real defects, the separation costs more than it gives. The D1 experiment compares hidden-test pass rates and test-caused retries between the separate tester and an implementer that writes its own tests.
