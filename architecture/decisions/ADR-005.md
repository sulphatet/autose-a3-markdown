# ADR-005: A tool layer per role, and separate GitHub identities

**Status:** Accepted
**Date:** 2026-11-21
**Decision area:** D5, tools

## Context

Each agent should be able to do only what its stage needs.

The agents run in a GitHub runner that also holds secrets: the Gemini key, the GitHub token, and the PAT for release. A generic bash tool gives a model everything the runner can do, including `curl`, `git push` and reading environment variables.

Two GitHub facts constrain the design:

- Events caused by the built-in `GITHUB_TOKEN` do not start other workflows. A branch pushed with it would never run CI, so the stage 5 check could never pass.
- GitHub does not let the account that opened a PR approve it or request changes on it. If one identity both opened and reviewed the PR, the reviewer could only leave comments.

## Decision

**Agent tools are Python functions defined by us** (`workflow/autose/tools.py`) and passed to Gemini as function declarations. Each role gets a fixed subset:

| Tool | Spec | Designer | Implementer | Tester | Reviewer |
| --- | --- | --- | --- | --- | --- |
| `list_dir`, `read_file`, `search` | — | yes | yes | yes | yes |
| `write_file`, `replace_in_file` (source paths) | — | — | yes | — | — |
| `write_file` (`tests/` only) | — | — | — | yes | — |
| `run` (allow-listed commands) | — | — | build, unit tests | unit tests | build, unit tests (optional) |
| `submit` (final structured answer) | yes | yes | yes | yes | yes |
| network, git, `gh` | no | no | no | no | no |

Every file tool resolves its path and refuses anything outside the working copy. It also refuses `.git/` and `.github/`, and, on the write side, anything the role is not allowed to write.

`run` accepts only commands from a fixed list (`python -m unittest …`, `python -m pip install -e .`, `python -c "import markdown"`, `flake8 …`). Commands run with a scrubbed environment: only `PATH`, `HOME` and `LANG`, with no secrets. They have a time limit.

**GitHub access is done only by orchestrator code**, never by agents. It uses the `gh` CLI:

| Identity | Used for | Rights |
| --- | --- | --- |
| `GITHUB_TOKEN` in `build` job | progress comments, `autose-state` branch | `contents: write`, `issues: write` |
| Fine-grained PAT `AUTOSE_PAT` (this repository only) | push `autose/issue-<n>`, open the PR | Contents and Pull requests: read/write, one repository |
| `GITHUB_TOKEN` in `review` job | post the review | `contents: read`, `pull-requests: write` |

Pushing and opening the PR as the PAT owner makes CI run on the PR. It also makes the PR author different from the reviewer identity (`github-actions[bot]`), so the review can formally approve or request changes. The PAT is only present in the environment of the release step.

`gh` is always called with `--repo sulphatet/autose-a3-markdown`. On a fork, `gh pr create` would otherwise target the upstream project, which the rules forbid.

## Alternatives considered

- **A generic bash tool (as in mini-swe-agent).** Very capable, but it cannot be limited per role, and it can read secrets from the environment. Rejected.
- **GitHub MCP server for agents.** Gives agents GitHub actions they do not need. No agent needs to talk to GitHub at all.
- **`GITHUB_TOKEN` for everything.** CI would not run on the PR, and the review could not approve or request changes. Rejected.
- **A GitHub App instead of a PAT.** Cleaner identity and short-lived tokens, but more setup than the assignment justifies. Noted as the production choice.

## Consequences

- An agent that is tricked by injected text can still only write files in its allowed area and run allow-listed commands. Exfiltration needs network access, which no tool gives.
- The allow-list may block a command an agent genuinely needs. That shows up as a refused tool call in the log, and the list is changed in code, which is visible in review.
- The PR appears to come from the repository owner's account. The PR body states it was generated by the workflow, and gives the run link.
- A leaked PAT can write to this one repository only. It is stored as a secret and deleted after grading.
