# ADR-012: Release runs inside the orchestrator; the PAT stays in its memory

**Status:** Accepted. Supersedes the sentence in ADR-005 "The PAT is only present in the environment of the release step".
**Date:** 2026-11-22
**Decision area:** D5 tools, D9 safety

## Context

ADR-005 planned a separate Actions step for release, so that the PAT would exist only in that step's environment.

While building, the CI-red loop made that impractical. When CI fails in stage 5, ADR-002 sends the work back to stage 3 *within the same run*. If release were a separate step, the loop back to stage 3 would have to cross step boundaries. That means either a second dispatch per CI failure, or running the agents in a later step again.

## Decision

`release.py` is called by the orchestrator in the same process. The step's environment contains `AUTOSE_PAT`.

The orchestrator removes it from its environment at start-up (`os.environ.pop`), keeps it in memory, and passes it only to two subprocesses: the `git push` of the code branch, through `GIT_CONFIG_*` variables that are never written to `.git/config`, and `gh pr create` / `gh pr edit`.

The same is done for `GEMINI_API_KEY` and `GITHUB_TOKEN`. Every command an agent runs gets a scrubbed environment (ADR-005).

## Alternatives considered

- **Separate release step, and a new dispatch on red CI.** Keeps the PAT out of the agent step's environment, but adds a run per CI failure and splits one attempt's log across runs.
- **No PAT; use `GITHUB_TOKEN` and trigger CI with `workflow_dispatch`.** Then the PR author would be the same bot as the reviewer, so the review could not approve or request changes (ADR-005).

## Consequences

- The PAT never reaches an agent's tool environment. But it is in the memory of a process on the same runner, and code that an agent writes (tests) runs on that runner as the same Unix user. A determined attacker who controlled that code could read the parent process's initial environment from `/proc`.
- This is recorded as a limitation in the report. The mitigations are the trusted-trigger gate (ADR-010), the PAT scoped to one repository, and protected `main`. The production fix would be to run agent commands as a separate Unix user, or in a container with no access to the parent process.
