# ADR-011: Send test-file problems back to the tester, not the implementer

**Status:** Accepted (refines ADR-002, found while building)
**Date:** 2026-11-22
**Decision area:** D2 control flow, D1 splitting the work

## Context

ADR-002 sends every stage 4 failure back to the implementer. While writing the stage 4 check, it became clear that some failures are the tester's fault, and the implementer cannot fix them:

- the test file is missing, has a syntax error, or fails flake8 (upstream CI lints `tests/`);
- a required test name (`test_AC_…`) is missing;
- every new test already passes on the base commit, so the tests do not check the change (the fail-to-pass rule, ADR-007).

The implementer may only write under `markdown/` and the changelog (ADR-005). Sending these failures to it would waste its three attempts, and then trigger a redesign for a problem that is in neither the code nor the design.

## Decision

Stage 4 failures are routed by **which artifact is at fault**. This is decided by code:

| Failure | Goes to | Budget |
| --- | --- | --- |
| Test file missing, syntax error, flake8, missing AC test names | Tester | 2 writes per design (`MAX_TEST_WRITES`) |
| New tests all pass on the base commit | Tester | same budget |
| New tests or the existing suite fail on the branch | Implementer | 3 attempts per design (ADR-002) |

When the tester's budget runs out, the run stops at stage 4 with the reason. Tests are written once per design. After a redesign, the old test file is removed and the tester writes it again from the new design.

## Alternatives considered

- **Keep ADR-002 as written.** Simpler, but known to waste attempts on failures the implementer cannot fix.
- **Let the implementer edit tests.** It would fix test problems, but then the implementer could also weaken tests until they pass, which defeats the point of a separate tester (ADR-001).

## Consequences

- If a test is wrong *in content* (it asserts the wrong behaviour but is well-formed and fails on base), it still goes to the implementer, which cannot fix it. That case ends in a redesign and a fresh test file, or a stop. This is a known limitation, and it is visible in `test_report.md`.
