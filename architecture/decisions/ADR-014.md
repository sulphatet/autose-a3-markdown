# ADR-014: Raise the run token budget to 8M

**Status:** Accepted. Supersedes the "Tokens per run: 2,000,000" row of ADR-009.
**Date:** 2026-11-22
**Decision area:** D9, budgets; D6, models

## Context

ADR-009 set a run budget of 2M tokens and said the limits "are guesses until real runs exist".

Evidence so far:

| Run | Stages reached | Model calls | Tokens |
| --- | --- | --- | --- |
| Local dry run, issue #2 (prompt v2) | S1-S4 passed first time | — | 357,556 |
| [Run 44941261187](https://github.com/sulphatet/autose-a3-markdown/actions/runs/44941261187), issue #2 | S3, 3rd attempt | 100 | 2,005,443 (prompt 1,992,284; output 13,159) |

99% of the tokens are prompt tokens. Each turn of the agent loop sends the whole conversation again, and every file read stays in that conversation. One implementer attempt of 30 to 40 turns therefore costs hundreds of thousands of tokens.

With 3 attempts, 1 redesign and up to 2 review rounds, a run that needs its retries cannot fit into 2M. The budget would stop it before ADR-002's retry rules ever take effect.

The models are on the free tier (ADR-006), so tokens cost no money. The binding limits are the per-minute and per-day request quotas, which ADR-009 handles with retries.

## Decision

Raise the run budget to **8,000,000 tokens**. That is about four full failing implementation attempts on top of a normal pass.

The other limits stay: 40 turns per agent, 3 repeated calls, and the job timeouts.

## Alternatives considered

- **Keep 2M and cut the context instead** (drop old tool outputs from the conversation). This is the better long-term fix, but it changes agent behaviour in ways not yet tested. Recorded as future work in the report.
- **No token budget, only the turn limits.** Turn limits already bound the cost, but a total budget is a clear, reportable stop rule, and the brief asks us to report tokens.

## Consequences

- A run can now use its full retry budget before the token budget stops it.
- If the free-tier daily quota runs out first, the run stops with "model unavailable" (ADR-009). That is reported as an infrastructure failure.
